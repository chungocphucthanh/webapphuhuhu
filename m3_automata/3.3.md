# 3.3 Regular constraints in the ILP

The implementation is in [regular_to_ilp.py](regular_to_ilp.py). It unfolds a complete DFA over the days of the exam period, turns acceptance into flow constraints, and adds them to the M2 model of [2.7](../m2_ilp/2.7.md) for the rules R1, R2 and R3 of [3.1](3.1.md).

## Layered graph

Let $\mathcal{A}=(Q,\Sigma,\delta,q_ 0,F)$ be a complete DFA over $\Sigma=\lbrace M,A,N,\texttt{-}\rbrace$ and $T$ the number of days. The layered graph has a node $(t,q)$ for every $t=0,\ldots,T$ and $q\in Q$, and an edge

$$(t,q,a):\ (t,q)\to(t+1,\delta(q,a)), \qquad t=0,\ldots,T-1,\ a\in\Sigma.$$

A word $w=w_ 1\cdots w_ T$ follows exactly one path from $(0,q_ 0)$, because $\delta$ is a function. The word is in $L(\mathcal{A})$ if and only if this path ends at a node $(T,q)$ with $q\in F$.

## Flow constraints

Let $s_ {t,a}\in\lbrace 0,1\rbrace$ be 1 when day $t$ reads the symbol $a$, so $\sum_ a s_ {t,a}=1$. One unit of flow runs from $(0,q_ 0)$ to the accepting nodes of layer $T$, with a variable $y_ {t,q,a}\in[0,1]$ on each kept edge:

| Row | Constraint |
|---|---|
| `SRC` | $\sum_ a y_ {0,q_ 0,a}=1$ |
| `FLOW` | $\sum_ a y_ {t,q,a}=\sum_ {(p,a):\,\delta(p,a)=q}y_ {t-1,p,a}$ for $t=1,\ldots,T-1$ |
| `LINK` | $\sum_ q y_ {t,q,a}=s_ {t,a}$ |

An edge gets a variable only if it lies on a path from $(0,q_ 0)$ to an accepting node of layer $T$ that uses the symbols allowed on each day. Edges into the trap state are therefore dropped, since no accepting state can be reached from it. Edges into a non-accepting node of layer $T$ are dropped too, which is the acceptance condition.

Claim. For binary $s$, these rows have a solution exactly when the word chosen by $s$ is in $L(\mathcal{A})$.

If the word is accepted, every edge of its path is kept, and $y=1$ on these $T$ edges satisfies all rows. Conversely, suppose the rows hold. By induction on $t$, all the flow of layer $t$ sits in the node $q_ t=\widehat{\delta}(q_ 0,w_ 1\cdots w_ t)$. For $t=0$ this is `SRC`. If it holds for $t$, `LINK` gives zero flow to every edge of day $t$ whose symbol is not $w_ {t+1}$, so the unit leaves $q_ t$ on the edge labelled $w_ {t+1}$ and reaches $q_ {t+1}$. That edge exists on the last layer only if $q_ T\in F$, so the word is accepted.

The proof uses only the integrality of $s$. Hence $y$ can stay continuous: when $s$ is integral, the flow is the 0/1 vector of one path. The number of variables grows with $T\cdot|Q|\cdot|\Sigma|$ per staff member, so the model uses the minimal DFA.

## Small example

Take R1 (no three working days in a row, states `run0`, `run1`, `run2`, `dead`) and $T=4$. The word `MM-M` follows `run0`, `run1`, `run2`, `run0`, `run1` and ends in an accepting state. The word `MMM-` would need the edge `run2` $\to$ `dead` on day 2, which has no variable, so no unit of flow can spell it. The layers contain 1, 2, 3 and 3 live nodes, giving $4+8+9+9=30$ edges. A brute-force enumeration confirms that the flow model has the same optimum as the best accepted word (see the functions below).

## Linking to the M2 variables

M2 chooses $x_ {ij}\in\lbrace 0,1\rbrace$ for $(i,j)\in A$, not a symbol per day. A session $j$ has the class $M$, $A$ or $N$ given by its start time (07:00 or 09:30, 13:00 or 15:30, 18:15), the same table as in [encode_strings.py](encode_strings.py). Let $J_ {t,a}(i)$ be the available sessions of staff member $i$ with class $a$ on calendar day $t$. The class indicator is

$$u_ {i,t,a}\ge x_ {ij}\quad(j\in J_ {t,a}(i)), \qquad u_ {i,t,a}\le\sum_ {j\in J_ {t,a}(i)}x_ {ij}.$$

For binary $x$, $u_ {i,t,a}=1$ exactly when $i$ has at least one session of class $a$ that day. M2 allows a morning and an afternoon session on the same day, because H2 forbids only sessions that overlap in time, so the day symbol cannot be $\sum_ j x_ {ij}$. With the priority $N>A>M$ of 3.1, the day symbol is a binary $z_ {i,t,a}$ with

$$z_ {i,t,a}\le u_ {i,t,a}, \qquad z_ {i,t,a}\le 1-u_ {i,t,h}\ (h\text{ outranks }a), \qquad z_ {i,t,a}\ge u_ {i,t,a}-\sum_ {h}u_ {i,t,h},$$

and $z_ {i,t,\texttt{-}}=1-\sum_ {a\in\lbrace M,A,N\rbrace}z_ {i,t,a}$. A staff member with a morning and an afternoon session on day $t$ has $u_ M=u_ A=1$, so $z_ M=0$, $z_ A=1$ and the day reads `A`. Where $J_ {t,a}(i)$ is empty, $u_ {i,t,a}$ and $z_ {i,t,a}$ are 0 and no variable is created. Finally each staff member gets its own flow with $s_ {t,a}=z_ {i,t,a}$, and the objective of M2 is unchanged.

The horizon is the $T=27$ calendar days from 18 May to 13 June 2026, including the days without exams. The machine starts in $q_ 0$ on day 0, so no work is assumed before the period.

## Re-solving M2

The automaton is the minimal product of R1, R2 and R3, read from the submitted JSON files: 259 reachable product states reduce to 15 states, including the trap. The comparison uses seed `1358677812`, seeded availability, $K=3$, the same two stages as M2 and CBC with a 150 s limit per stage. Run it from the repository root:

```bash
python -m m3_automata.regular_to_ilp
```

| Measure | Baseline | M2 alone | M2 + R1, R2, R3 |
|---|---:|---:|---:|
| `max_load` | 19 | 11 | 11 |
| L1 | 115.397 | 36.329 | 36.329 |
| LOC | 162 | 28 | 36 |
| Stage-2 objective | 264.777 | 59.849 | 66.569 |
| Staff breaking R1 / R2 / R3 | 28 / 5 / 3 | 44 / 6 / 14 | 0 / 0 / 0 |
| Staff accepted by all three | 41 | 24 | 73 |
| Stage 1 variables / rows | | 2,594 / 798 | 18,817 / 19,121 |
| Stage 2 variables / rows | | 4,377 / 3,372 | 20,600 / 21,695 |
| Solve time, stages 1 + 2 | | about 0.3 s | about 13 s |

Both models reach $t^*=11=\lceil 769/73\rceil$, the lower bound for integer loads, so the rules cost no maximum load and no L1. They cost location: 8 more assignments go to the other campus, and $0.84\times 8=6.72$ is the increase of the objective. M2 alone ignores the order of days and breaks the rules more often than the baseline. The added rows are 16,223 variables (`ucls` 1,622, `zsym` 1,622, `yflow` 12,979) and 18,323 constraints in each stage; only 12,979 of the 66,576 possible flow edges are kept because each staff member has few available symbols per day. Solve times vary with the machine; the other values do not.

The command stops with an error unless all of these hold:

- the M2 validator reports no violation of H1 to H3;
- for every staff member, the word read from $z$, the word read from the flow $y$ and the word rebuilt from $x$ are equal, and the DFA accepts it;
- each submitted DFA and the 15-state product accept all 73 words;
- the flow model has the same optimum as brute force in 16 small cases: four automata (R1, R2, R3, their product), two objectives, with and without fixed days, $T=7$.

It also re-solves with continuous $z$ and gets the same objective, 66.569, so only $x$ needs to be integral. The results are written to `extra/regular_to_ilp.json`.

## Functions in the code

- `session_class(inst)`, `calendar(inst)`, `sessions_by_class(inst)`: the class of each session, the 27 days, and the sets $J_ {t,a}$.
- `roster_strings(inst, assigned)`: one word per staff member; on the baseline it equals `encode_strings()`.
- `load_rules()`, `combined_dfa()`: the submitted DFAs and their minimal product.
- `layered_edges(dfa, allowed)`, `add_regular_constraint(prob, dfa, symbols, tag)`: the kept edges, and the rows `SRC`, `FLOW` and `LINK` for any complete DFA.
- `add_rules_to_m2(prob, x, inst, dfa)`, `solve_with_rules(inst, config, dfa)`: $u$, $z$ and one flow per staff member, and the two-stage solve.
- `check_rule_solution`, `violations`, `brute_force_check`, `compare`, `run_m3_ilp`: the checks and the comparison above.

The tests are in [test_regular_to_ilp.py](tests/test_regular_to_ilp.py).

## Limits

R4 is not added to the ILP: its product with R1, R2 and R3 has 99 states ([DECISIONS.md](../DECISIONS.md)), which makes the model larger and slower. The rule $|\#M-\#A|\le c$ at all times could instead be written as $2T$ linear rows per staff member on the variables $z$. Both stages are solved to optimality within the time limit; a schedule from a stage that stopped at the limit would depend on the machine. Several schedules can share the optimal value, and a change such as continuous $z$ may return a different one. `combined_dfa` builds the product itself, so it can be replaced by a separate product and minimisation module. The rules read one symbol per day with the priority $N>A>M$, and treat the 18:15 session as a night shift, as stated in [DECISIONS.md](../DECISIONS.md).
