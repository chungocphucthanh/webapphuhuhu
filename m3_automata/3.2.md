# 3.2 Product and minimization

The implementation is in [product_min.py](product_min.py). It combines the complete DFAs of [3.1](3.1.md) into one automaton and shrinks that automaton to its minimal form. The ILP of [3.3](3.3.md) uses the result, because its size grows with the number of states.

## Product

Let $\mathcal{A}_ i=(Q_ i,\Sigma,\delta_ i,q_ {0,i},F_ i)$ for $i=1,\ldots,k$ be complete DFAs over the same alphabet. The product is

$$
\mathcal{P}=\Bigl(Q_ 1\times\cdots\times Q_ k,\ \Sigma,\ \delta,\ (q_ {0,1},\ldots,q_ {0,k}),\ F_ 1\times\cdots\times F_ k\Bigr),
\qquad
\delta\bigl((p_ 1,\ldots,p_ k),a\bigr)=\bigl(\delta_ 1(p_ 1,a),\ldots,\delta_ k(p_ k,a)\bigr).
$$

By induction on $|w|$, $\widehat{\delta}(\text{start},w)=(\widehat{\delta}_ 1(q_ {0,1},w),\ldots,\widehat{\delta}_ k(q_ {0,k},w))$. Hence $\mathcal{P}$ accepts $w$ exactly when every factor accepts it, so $L(\mathcal{P})=\bigcap_ i L(\mathcal{A}_ i)$. Only tuples reachable from the start are built.

## Minimization

Two states $p,q$ are equivalent when, for every word $u$, $\widehat{\delta}(p,u)\in F\iff\widehat{\delta}(q,u)\in F$. After removing unreachable states, the equivalence classes are the states of the minimal DFA (Myhill-Nerode). They are found by partition refinement: start with the blocks $F$ and $Q\setminus F$, and split a block whenever two of its states reach different blocks on some symbol. The process stops after at most $|Q|$ rounds, and the blocks left are the classes. Merging each block gives a complete DFA with the same language. The trap state stays a single block named `dead`.

## Small example

Take R1 and R2 of 3.1. The product has 11 reachable states. The five accepting ones are `run0|free`, `run1|free`, `run1|after_night`, `run2|free` and `run2|after_night`; the other six, such as `run2|dead`, never accept again and form one block, `dead`.

| Round | Split of the accepting block |
|---|---|
| 1 | on `M`, `run0\|free` and `run1\|free` stay accepting, but `run1\|after_night`, `run2\|free` and `run2\|after_night` reach a rejecting state |
| 2 | on `M`, `run0\|free` reaches `run1\|free`, while `run1\|free` reaches `run2\|free`, which are in different blocks |
| 3 | no block splits |

The result has 4 states: `run0|free`, `run1|free`, the block of `run1|after_night`, `run2|free` and `run2|after_night` (a rest day is required next), and `dead`. It is the DFA of "no three working days in a row, no work right after N".

## Results

Counts include the trap state. They come from `python -m m3_automata.product_min`.

| Automaton | Reachable | Minimal |
|---|---:|---:|
| R1 | 4 | 4 |
| R2 | 3 | 3 |
| R3 | 58 | 36 |
| R4 (c = 3) | 8 | 8 |
| R1 x R2 | 11 | 4 |
| R1 x R2 x R3 | 259 | 15 |
| R1 x R2 x R3 x R4 | 2072 | 99 |

R3 shrinks because a history $h$ keeps bits that cannot matter any more: for example `w111000` and `w000000` have the same future, since the three ones leave the window before three new working days can push the count above four. R1 x R2 x R3 is the automaton given to the ILP.

## Functions in the code

- `product(machines)`: reachable product of complete DFAs with the same alphabet; a state is named `p|q|...`.
- `minimize(dfa)`: minimal complete DFA of the language; the trap block is called `dead`.
- `load_rule(name)`: load the DFA JSON of R1 to R4.
- `write_minimization()`: write the R1 x R2 x R3 counts to `minimization.json`.
- `counts_table(names)`: rows `(automaton, reachable, minimal)` for each rule and for the products R1 x R2, R1 x R2 x R3, and so on. A rule whose JSON file is missing is skipped.

## Limits

Minimization removes states of the product only; it does not change the language. The size of the minimal DFA is not bounded by a formula here: the table lists the measured values. `regular_to_ilp.py` still uses its own `_product` and `_minimize`, which give the same counts.
