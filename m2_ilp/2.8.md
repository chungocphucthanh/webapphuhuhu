## When the model is infeasible: relaxing H3

If stage 1 is `infeasible`, `solve` calls `tuning.diagnose` and re-solves with
$$\sum_{i:(i,j)\in A} x_{ij} + u_j = r_j,\quad u_j \ge 0,\qquad \min\ t + M_{el}\sum_j u_j,\quad M_{el} = 1000.$$
The relaxed model is always feasible ($x = 0$, $u = r$). Because $M_{el}$ is larger than any possible benefit in $t$,
the optimum first reduces the total number of missing people, and only then the max load. The sessions with $u_j > 0$ are the
capacity rows that cannot be kept together with H1, H2: this is the ILP version of the **UNSAT core** in M1.

**Link to M1.** Run on the UNSAT slice that M1 generates from the seed (`prepare_instances(seed)["unsat"]`,
5 people, 4 sessions, shift code 20260610_2 with $r-1 = 0$ free people retained):

| | Result |
|---|---|
| M2 `solve` | `infeasible` → diagnosis: session `20260610_2_CS2`, needs 1, short by 1 |
| M1 minimal unsat core | `capacity(20260610_2_CS2)=1` + `Busy(CB001/CB002/CB006/CB063/CB066, 20260610_2_CS2)` |

The two modules point to the same session: M1's core says *why* (capacity + all 5 Busy), while M2's $u_j$ says
*how much is missing*. To obtain a schedule, exactly that constraint must be relaxed (add free people or reduce $r_j$);
no weighting or LP relaxation can rescue it.

## Sensitivity analysis (re-weight)

Each weight is multiplied by 0.5, 1, 2 (one weight at a time), and $K \in \{2, 3, 4\}$, on the prefix slices
of **1, 2, 3 weeks and the full** data (slices are chosen by schedule, not by outcome). The table lists only
the settings that change the solution; every other setting gives exactly the original solution.

| Scope | Original solution (max, L1, LOC, FAT, TRV) | Setting that changes the solution | New solution |
|---|---|---|---|
| 1 week | 1; 22.623; 0; 0; 0 | none | — |
| 2 weeks | 2; 34.521; 0; 0; 0 | none | — |
| 3 weeks | 7; 28.110; 17; 0; 0 | $\lambda_{LOC}\times 2$ (1.68) | 7; 48.822; 3; 0; 0 |
| 3 weeks | | $K = 2$ | 7; 28.110; 19; 0; 0 |
| Full | 11; 36.329; 28; 0; 0 | $K = 2$ | 11; 36.329; 50; 0; 0 |

Observations:

1. **Max load never changes**: stage 1 is separate, so the soft weights cannot sacrifice the
   grading criterion (a benefit of D2).
2. **LOC trades off against L1 fairness.** On the 3-week slice, when $\lambda_{LOC}$ doubles, the solver
   accepts an L1 increase of 20.71 to reduce LOC by 14. The two solutions tie at
   $\lambda_{LOC} = 20.71/14 \approx 1.48$, which lies between 0.84 and 1.68. The team's weight (0.84) is
   below this threshold, so fairness is prioritized over campus preference. On the full data, the solution does not change
   even at $\lambda_{LOC} = 1.68$: each session against preference removed from the remaining 28 would have to
   cost more than 1.68 units of L1.
3. **FAT and TRV are 0 in every setting**: the seeded availability is wide enough to completely avoid days with
   more than $K$ sessions and days working at two campuses without costing any L1. Therefore $\lambda_{FAT}$, $\lambda_{TRV}$ within
   [0.5×; 2×] do not affect the solution: these two soft constraints are "free" on the team's instance.
4. **$K$ has a real effect:** $K = 2$ still keeps FAT = 0 but pays for it with LOC (28 → 50 on the full
   data). $K = 4$ gives the same solution as $K = 3$. This supports the choice of $K = 3$ made from data (2.5):
   a tighter value would damage campus preferences with no justification from the original schedule.
