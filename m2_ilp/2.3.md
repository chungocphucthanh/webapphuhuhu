# 2.3 Objective function

The implementation is in [objective.py](objective.py). A staff member's load is measured in sessions, not hours:

$$w_i = \sum_{j:(i,j)\in A} x_{ij}.$$

## Two stages

First, minimize the highest individual session load. Add a variable $t \ge 0$ and solve:

$$\min t, \qquad w_i \le t \quad \forall i\in I.$$

Exact staffing and no-overlap constraints must remain in place. Let the optimal value of this stage be $t^*$.

In stage 2, add $t \le t^*$, then minimize load deviation and soft penalties:

$$\min \sum_{i\in I}\delta_i
  + \lambda_{LOC}\,LOC + \lambda_{FAT}\,FAT + \lambda_{TRV}\,TRV.$$

This approach does not trade a higher maximum load for lower soft penalties. However, stage 2 combines L1 and penalties in a weighted sum, so L1 does not have absolute priority over soft penalties.

## Linearizing load deviation

When each session is assigned exactly its required number of staff $r_j$, total load is constant:

$$\sum_i w_i = \sum_j r_j, \qquad
\bar w = \frac{\sum_j r_j}{|I|}.$$

Use two constraints for each staff member:

$$\delta_i \ge w_i-\bar w, \qquad
\delta_i \ge \bar w-w_i, \qquad \delta_i\ge 0.$$

Because $\delta_i$ is minimized, it equals $|w_i-\bar w|$ at optimality. Thus $L1=\sum_i\delta_i$ remains a linear objective. Variance uses squared deviations and would create a quadratic objective.

`add_objective()` receives the `location`, `fatigue`, and `travel` expressions through `soft_terms`. Weights come from `config.lambdas(inst)` in the same order as these three components; the weight data is described in [2.6](2.6.md).

## Optional chord constraint

For integer loads and a non-integer $\bar w$, let $L=\lfloor\bar w\rfloor$ and $f(w)=|w-\bar w|$. The following constraint can be added:

$$\delta_i \ge f(L)+\bigl(f(L+1)-f(L)\bigr)(w_i-L).$$

This line does not exceed $f(w)$ at integer loads, so it does not exclude valid integer schedules. It strengthens the LP relaxation between $L$ and $L+1$. Enable it with `config.l1_chord`; no additional constraint is needed when the mean is an integer.

This inequality relies on integrality. Using it in the LP measures a relaxation with an additional valid inequality for the integer problem, rather than merely replacing binary variables with continuous variables. It does not guarantee that the LP bound equals the integer optimum of the full model.

## Small example

There are 3 staff members and 4 sessions, each requiring 1 person; each person can receive at most 2 sessions. Then $\bar w=4/3$.

| Loads of the 3 staff members | Maximum load | L1 |
|---|---:|---:|
| $(2,1,1)$ | 2 | $4/3$ |
| $(2,2,0)$ | 2 | $8/3$ |

Both load profiles achieve a min-max value of 2. Without soft penalties, stage 2 chooses $(2,1,1)$ because its L1 is smaller. This is a hand-calculated example, not a benchmark result on the full dataset.

## Functions in the code

- `mean_load(inst)`: compute the mean from demand and staff count.
- `l1_chord(w_bar)`: return the chord coefficients, or `None` when the mean is an integer.
- `add_objective(prob, x, w, inst, config, soft_terms, slack=None)`: add the objective for one stage and return variables and expressions for reading results.

Each problem calls `add_objective()` once; the two stages use separate problems. Stage 2 requires `config.t_cap` from the optimal stage-1 solution. The other configuration fields used are `stage`, `l1_chord`, and `elastic_penalty`, along with the `lambdas(inst)` method.

If `slack` is supplied, the code adds `elastic_penalty * sum(slack)` to the objective. This penalizes violations and is not equivalent to retaining hard constraints. The mean formula above assumes that total load still equals total demand; do not use this interpretation if slack changes total load.
