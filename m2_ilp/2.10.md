# 2.10 Counterexamples: two wrong models

> Owner: TV2 Chu Ngọc Phúc Thành. Code: [counterexample.py](counterexample.py), which writes
> `m2_ilp/counterexample.json`. Tests: [test_counterexample.py](test_counterexample.py).

The brief asks for one plausible but wrong modelling choice and a concrete schedule it admits,
with the reason that schedule is invalid. We give both choices the brief suggests, each as one
`ModelConfig` flag on the same code path as the real model ([2.7](2.7.md)):

| Wrong model | Flag | What it admits |
|---|---|---|
| (a) Drop the overlap constraint H2 | `drop_overlap=True` | A person working two campuses at the same time |
| (b) Relax $x$ to a continuous LP | `relax_integrality=True` | Fractions of a person; a load no integer schedule can reach |

Every number below is produced by `counterexample.py`; none is typed by hand. Run
`python run_all.py --seed $(cat data/seed.txt) --stage m2` or `python -m m2_ilp.counterexample`
from the repository root.

## (a) Dropping H2 (no double-booking)

### Why it looks reasonable

All 18 overlapping pairs in the data are the CS1 and CS2 sessions of one shift code at identical
times ([2.4](2.4.md)). The stage-2 objective already charges $\lambda_{TRV} = 1.97$ for every day a
person works both campuses ([2.5](2.5.md)). It is tempting to conclude that the travel penalty
already keeps people off two campuses in one shift, so the 642 H2 rows are redundant and can be
dropped to shrink the model.

### Why it is wrong

- TRV is a **price, not a ban**. The solver pays it whenever the fairness gain is larger.
- TRV only knows that a person works two campuses on the same day. It cannot tell back-to-back
  sessions, which are allowed, from simultaneous ones, which are impossible.
- The soft terms exist only in **stage 2**. Stage 1 minimises the maximum load $t$ with no
  penalty at all, so without H2 it can choose a $t^*$ that only a double-booked schedule reaches.
  Stage 2 must then respect $t \le t^*$ and has no valid schedule left to choose.

### Instance used

On the default instance (`seeded`, `flip_rate=0.30`) availability is wide, and dropping H2
rarely helps fairness:

| Default instance | max load | L1 | H2 violations |
|---|---:|---:|---:|
| Correct model, fairness only | 11 | 36.329 | 0 |
| Wrong model, fairness only | 11 | 36.329 | 16 |
| Correct model, with soft terms | 11 | 36.329 | 0 |
| Wrong model, with soft terms | 11 | 36.329 | 0 |

Even here, the fairness-only wrong model returns a schedule with 16 double-bookings, reported as
optimal with exactly the same objective, so the error is invisible from the objective alone.
With the soft terms on, TRV happens to steer it to a valid schedule. That is luck, not a proof.

To show the wrong model *preferring* an invalid schedule, `counterexample.py` uses M1's Busy
reading (forum d=33734): a person is available only for the shift codes they worked in the
baseline, i.e. `seeded` with `flip_rate=0`, giving $|A| = 1{,}125$. The number of available people
per shift code then equals its demand, so H2 actually binds. This instance is fixed in the code
before solving; it is not chosen from the results.

### Concrete invalid schedule

`drop_overlap_example` solves the correct and the wrong model, fairness only, on the prefix
slices `small_slice(inst, n)` for $n = 1, 2, \dots$ exam days, in calendar order. It stops at the
first slice where the wrong optimum is invalid **and** strictly fairer by (max load, L1). That is
$n = 9$ exam days: 40 staff, 17 sessions, 1 overlapping pair.

| 9-day slice | $t^*$ | max load | L1 | spread | H2 violations |
|---|---:|---:|---:|---:|---:|
| Correct model | 5 | 5 | 36.25 | 4 | 0 |
| Wrong model (`drop_overlap`) | 5 | 5 | **35.00** | 4 | **1** |

The wrong optimum assigns **CB032 to both `20260528_3_CS1` and `20260528_3_CS2`, 13:00–15:30
on 2026-05-28**: one person invigilating two rooms on two campuses at the same time. It reports
L1 = 35.00, which looks fairer than the true optimum 36.25, so a team comparing objectives would
prefer the wrong model. The independent validator ([2.4](2.4.md)) rejects it with:

```text
H2: CB032 works 20260528_3_CS1 and 20260528_3_CS2, both 13:00-15:30 on 2026-05-28
```

### Effect on the full data: a false "beats baseline"

On the full data of the same instance, with the full model (soft terms on):

| Full data, flip_rate=0 | max load | L1 | H2 violations | Double-booked staff |
|---|---:|---:|---:|---:|
| Baseline | 19 | 115.397 | 0 | 0 |
| Correct model | 19 | 115.397 | 0 | 0 |
| Wrong model | **12** | 79.260 | **19** | **12** |

The correct model proves that 19 is the best possible max load when availability is this tight,
so nothing beats the baseline. The wrong model reports max load 12 and would set
`beats_baseline = true`, which is false: 12 people are booked into overlapping sessions 19 times.
TRV did not prevent it, because stage 1 had already fixed $t^* = 12$, which no valid schedule
reaches. This is why `run_m2` refuses to write outputs unless the validator reports zero
violations.

## (b) Relaxing $x_{ij} \in \{0,1\}$ to $x_{ij} \in [0,1]$

### Why it looks reasonable

Assignment and transportation problems have totally unimodular constraint matrices, so their LP
relaxation already has integer optimal vertices. One might assume this model is the same and solve
it as an LP, which is faster and needs no branch-and-bound.

### Why it is wrong

The min-max objective adds the column of $t$ to the rows $w_i \le t$ (and on the real data H2 adds
clique rows). The resulting matrix is not totally unimodular. The fractional optimal vertex below,
found with integer right-hand sides, proves it. The LP spreads people over several sessions to
push $t$ down to the average load $\sum_j r_j / |I|$, which an integer schedule cannot reach.

### Concrete invalid schedule

The instance is the brief's Module 2 worked example (`fixtures.lp_gap_instance`): 3 staff, 4
back-to-back sessions S1–S4 on one day, each needing 1 person, everyone available, no overlaps.
We solve stage 1 (min $t$) with `relax_integrality=True` and with binary $x$:

| | $t$ | Loads (CB1, CB2, CB3) |
|---|---:|---|
| LP relaxation | $Z_{LP} = 4/3$ | $4/3,\ 4/3,\ 4/3$ |
| ILP | $Z_{ILP} = t^* = 2$ | $2,\ 1,\ 1$ (validator: 0 violations) |

The LP optimum CBC returns:

| | S1 | S2 | S3 | S4 |
|---|---:|---:|---:|---:|
| CB1 | 1 | 0 | **1/3** | 0 |
| CB2 | 0 | 1 | **1/3** | 0 |
| CB3 | 0 | 0 | **1/3** | 1 |

Every LP row holds: S3 gets $\tfrac13 + \tfrac13 + \tfrac13 = 1$ person and every load is
$\tfrac43 \le t$. As a schedule it is invalid: session S3 is covered by a third of each of three
people, and nobody actually has to be there. The validator works on integer pairs, so it cannot
read this solution directly. Any rounding fails, though. Rounding at $\tfrac12$ leaves S3 empty:

```text
H3: S3 needs 1 staff, got 0
```

Rounding every positive value up puts 3 people in S3 (H3 again) and gives a max load of 2, not
the reported $4/3$. The LP value is only a **lower bound**, $Z_{LP} \le Z_{ILP}$, strict here.
On the full data the stage-1 LP gives $Z_{LP} = 769/73 \approx 10.534$ against $t^* = 11$
(`performance.json`, see [2.9](2.9.md)). The model therefore keeps $x$ binary, and the LP is used only for bounds.
