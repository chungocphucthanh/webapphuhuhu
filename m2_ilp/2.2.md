## 3. Variable definitions

For every `(i, j)` in `A`:

```text
x[i,j] = 1 if person i is assigned to session j; 0 otherwise
w[i]   = sum of x[i,j] over that person's available sessions
```

`create_variables` creates only available pairs. A missing pair is forbidden and implicitly zero; it is not an assignment variable that still needs to be added.

| Item                      | Type/domain               | Count on the current full instance |
| ------------------------- | ------------------------- | ---------------------------------- |
| `x[i,j]`                  | Binary `{0,1}` by default | 2,593 variables                    |
| `x[i,j]` in LP relaxation | Continuous `[0,1]`        | The same 2,593 variables           |
| `w[i]`                    | Linear sum expression     | 73 expressions, no extra variables |

Creating all pairs would require 6,059 variables (`73 × 83`). Restricting variables to `A` reduces model size and excludes forbidden assignments.

`config.relax_integrality` selects the domain. A continuous relaxation can return fractional assignments and is not a valid final personnel schedule. It supports tuning/relaxation analysis; the final assignment model uses binary variables.

Names follow `x_i_j`, with the instance's zero-based indices. The function returns `(x, w)` as dictionaries. It does not add constraints or an objective. The other owners create auxiliary variables for peak load, deviations, fatigue, and travel.

Use `w_i` for workload in the report, keeping it distinct from deviation variables introduced by the objective owner and from the demand `r_j` defined in [2.1](2.1.md).

## 4. Explanation of `create_variables(prob, inst, config)`

Validate the relaxation flag and available-pair indices, and reject duplicate assignment-variable names in the problem. Create the variables, register them with the supplied PuLP problem, and construct workload sums. A person without available pairs has workload expression zero. Return `(x, w)` without adding constraints or an objective.

Checks performed, in order:

1. `config.relax_integrality` must be exactly `True` or `False`.
2. Every `(i, j)` in `A` must be an integer pair inside the instance bounds.
3. No variable named `x_i_j` may already exist in `prob`.

The variable category is `Continuous` when the relaxation is on and `Binary` otherwise; both use bounds `[0, 1]`.

## 5. Running and calling

```python
from m2_ilp.instance import build_instance
from m2_ilp.variables import create_variables

inst = build_instance(seed)

```

Lead creates `prob` and supplies `config.relax_integrality` as a boolean. When summing assignments by session, check whether `(i, j)` exists in `x`; unavailable pairs deliberately have no variable.

### Integration points

- **Baseline comparison:** the supplied forum clarification uses maximum workload for `beats_baseline`. For the full dataset, a valid schedule must have `max_load < 19`, where load is the value of `w[i]` in the solved schedule. Improving L1 alone does not meet that comparison.
- **Output:** the final schedule needs `invigilator_id`, `session_id`, and `assigned`; the forum permits extra columns. `assigned` comes from the solved value of `x[i,j]`. Lead exports the schedule after solving and validation. The preference CSV in [2.6](2.6.md) does not replace it.
- **Completion:** creating variables and a toy check do not establish that all M2 requirements pass. The integrated model must still be solved, validated, compared with baseline, and reproduced through the final pipeline.
